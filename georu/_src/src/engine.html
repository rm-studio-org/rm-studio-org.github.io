9[[이관 엔진||Migration engine]]

[[테이블 하나가 Spring Batch Job 하나입니다. 엔진은 읽기와 쓰기 사이에 메모리 큐를 두어 둘을 분리합니다. 소스는 PK 순서로 꾸준히 읽고, 여러 적재 스레드가 큐에서 꺼내 타겟에 배치로 씁니다. 느린 타겟이 소스 커서를 오래 붙잡지 않고, 적재 병렬도는 타겟 여유에 맞춰 조절할 수 있습니다.||One table is one Spring Batch Job. The engine puts an in-memory queue between reads and writes. The source is read steadily in PK order, while several load threads take rows off the queue and batch-write them to the target. A slow target never holds the source cursor for long, and write parallelism can be tuned to the target's capacity.]]

[[실패 대응은 자동에서 수동 순으로 쌓여 있습니다. 일시적인 오류는 엔진이 스스로 넘기고, 사람이 개입해야 할 때도 지우지 않고 빠진 행만 채우는 방법이 먼저입니다.||Failure handling is layered from automatic to manual.
