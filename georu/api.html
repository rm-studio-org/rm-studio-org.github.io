2인증 · 권한Authentication · permissions

화면과 같은 계정으로 HTTP Basic 을 보냅니다. HTTP Basic 호출에는 CSRF 토큰이 필요 없습니다. 권한은 화면의 메뉴 권한과 같습니다 — 실행은 실행, 조회는 조회 단계가 필요하고, 권한표에 없는 API 는 관리자만 부를 수 있습니다.Send HTTP Basic with the same account used on the screens; HTTP Basic calls need no CSRF token. Permissions mirror the UI menu permissions — runs need the Execute level, queries need View, and APIs not in the permission table are admin-only.

# 아래 예는 셸 변수를 씁니다The examples below use shell variables
$ B=http://<server>:<port>
$ U=<username>:<password>
$ curl -u $U $B/api/account/me
첫 로그인 전Before first sign-in

관리자가 만든 계정은 비밀번호를 바꾸기 전에는 POST /api/account/password 만 됩니다. 나머지는 403 PASSWORD_CHANGE_REQUIRED.Accounts created by an administrator can only call POST /api/account/password until the password is changed; everything else returns 403 PASSWORD_CHANGE_REQUIRED.

요청이 거치는 순서는 보안 필터 체인을 참고하세요.See the security filter chain for the order a request goes through.

4실행 요청 — POST /api/migrate/tableRun request — POST /api/migrate/table

6호출 예Examples

① 테이블 하나 — READER_TEST (적재 없음)① One table — READER_TEST (no writes)

$ curl -u $U -X POST $B/api/migrate/table -H 'Content-Type: application/json' -d '{
  "pluginName": "acme.member", "tableName": "tb_member",
  "tenantLevel1": "ACME", "tenantLevel2": "ACME", "tenantLevel3": "ACME",
  "tenantLevel4": "ACME", "tenantLevel5": "ACME",
  "testMode": "READER_TEST", "testMaxItems": 5 }'

응답 data.migrationId 로 결과를 봅니다. 실행은 백그라운드입니다.Follow the result with data.migrationId; the run is in the background.

② 진행 · 결과 · 오류 로그② Progress · result · error logs

$ curl -u $U $B/api/migration/chunks/<migrationId>/progress
$ curl -u $U "$B/api/report/jobs/<migrationId>?format=json"
$ curl -u $U "$B/api/report/jobs/<migrationId>/logs?level=ERROR"
$ curl -u $U "$B/api/report/jobs/<migrationId>?format=xlsx" -o result.xlsx

③ 실행 전 점검 (적재 없음)③ Precheck (no writes)

$ curl -u $U -X POST $B/api/precheck -H 'Content-Type: application/json' -d '{
  "pluginName": "acme.member", "tableNames": ["tb_member"],
  "tenantLevel1": "ACME", "tenantLevel2": "ACME", "tenantLevel3": "ACME",
  "tenantLevel4": "ACME", "tenantLevel5": "ACME" }'
$ curl -u $U $B/api/precheck/<runId>                     # RUNNING → result
$ curl -u $U "$B/api/precheck/<runId>/export?format=xlsx" -o precheck.xlsx

tableNames 를 비우면 플러그인 전체 테이블입니다.An empty tableNames means every table in the plugin.

④ 기간 + 날짜 분할 NORMAL④ Period + date split, NORMAL

$ curl -u $U -X POST $B/api/migrate/table -H 'Content-Type: application/json' -d '{
  "pluginName": "acme.order", "tableName": "tb_order",
  "tenantLevel1": "ACME", "tenantLevel2": "ACME", "tenantLevel3": "ACME",
  "tenantLevel4": "ACME", "tenantLevel5": "ACME",
  "testMode": "NORMAL", "startDate": "20250101", "endDate": "20251231",
  "enableDateDivision": true, "dateDivideUnit": "1m", "onUnitFailure": "STOP" }'
$ curl -u $U $B/api/migrate/groups/<groupId>

⑤ 시나리오 사전 확인 → 실행 → 진행 → 중지⑤ Scenario pre-confirm → run → progress → stop

$ curl -u $U $B/api/scenarios
$ curl -u $U -X POST $B/api/scenarios/<id>/check -H 'Content-Type: application/json' -d '{"testMode":"NORMAL"}'
$ curl -u $U -X POST $B/api/scenarios/<id>/run   -H 'Content-Type: application/json' -d '{"testMode":"NORMAL"}'
$ curl -u $U $B/api/migrate/groups/<groupId>
$ curl -u $U -X POST $B/api/migrate/groups/<groupId>/stop

중지는 지금 Job 이 끝나면 다음 Job 을 내지 않는 방식입니다.Stop lets the current Job finish and does not start the next one.

⑥ 실패한 실행의 빠진 행 채우기⑥ Fill missing rows of a failed run

$ curl -u $U $B/api/migrate/jobs/<migrationId>/fill-missing           # check eligibility · reason
$ curl -u $U -X POST $B/api/migrate/jobs/<migrationId>/fill-missing

⑦ 스케줄 전체 일시정지 · 지금 실행 중인 것⑦ Pause all schedules · what is running now

$ curl -u $U -X POST $B/api/migrate/schedules/pause-all
$ curl -u $U $B/api/migrate/gate
주의Caution

게이트 강제 해제(POST /api/migrate/gate/release)는 실행이 정말 없을 때만 씁니다.Use the gate force-release (POST /api/migrate/gate/release) only when nothing is really running.
