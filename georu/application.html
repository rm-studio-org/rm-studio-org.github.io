4프론트엔드 구성Frontend

운영 UI 는 서버 렌더(Thymeleaf) 화면 28개로, 별도 프론트엔드 빌드 없이 georu-ui jar 안에 들어 있습니다. 화면은 틀만 그려 보내고, 데이터는 공통 스크립트가 운영 API 를 불러 채웁니다. 따라서 화면에서 할 수 있는 일은 모두 API 로도 할 수 있습니다.The operation UI is 28 server-rendered (Thymeleaf) screens inside the georu-ui jar, with no separate frontend build. The server renders the frame; shared scripts call the operation API to fill in data — so anything a screen can do, the API can do too.

4.2 메뉴와 권한4.2 Menus and permissions

권한은 메뉴마다 없음 · 조회 · 실행 세 단계입니다. 기본 권한은 관리자 · 실행자 · 조회자이며 추가할 수 있습니다.Permissions are set per menu in three levels: None · View · Execute. Default roles are Administrator · Executor · Viewer, and more can be added.

4.3 화면 하나의 동작4.3 How a screen works

  1. 화면 요청Screen request브라우저가 /ui/... 요청 → 로그인 · 권한 확인 → 서버가 화면을 그려 보냅니다.The browser requests /ui/... → sign-in · permission check → the server renders and sends the screen.
  2. 데이터 채우기Fill data공통 스크립트가 /api/... 를 불러 데이터를 채웁니다 (CSRF 토큰 헤더).Shared scripts call /api/... to fill in data (CSRF token header).
  3. 실행 · 변경Run · change확인창(NORMAL 은 빨간 실행 바) → API → 결과는 패널 · 알림으로.Confirmation dialog (a red run bar for NORMAL) → API → results in panels · notifications.
  4. 서버 측 보호Server-side guard버튼을 숨기는 것과 별개로 서버가 모든 API 를 권한표로 막습니다.Independently of hidden buttons, the server guards every API with the permission table.

5백엔드 구성Backend

5.1 요청 처리 레이어5.1 Request processing layers

설계 포인트Design point

서비스 레이어의 비동기 실행기는 스레드가 정확히 1개여야 합니다. 1이 아니면 앱이 기동하지 않습니다. 이것이 "시스템 전체에서 실행은 하나"를 코드 수준에서 보장하는 두 번째 장치입니다(첫 번째는 실행 게이트).The service layer's async executor must have exactly one thread; otherwise the app refuses to start. This is the second mechanism that enforces "one run system-wide" at code level (the first is the execution gate).

5.2보안 필터 체인Security filter chain

모든 요청은 아래 7단계를 순서대로 지납니다. 앞 단계에서 막히면 뒤 단계는 돌지 않습니다.Every request passes the seven stages below in order; a failure stops the chain.

  1. 초기 설정 확인Initial setup check총관리자가 없으면 화면은 /setup, API 는 503 (30초 기억)Without a super administrator, screens go to /setup and the API returns 503 (cached 30 s) → 503 SETUP_REQUIRED
  2. CSRF화면 요청은 쿠키 토큰 · 헤더 확인, HTTP Basic 호출은 제외Screen requests check cookie token · header; HTTP Basic calls are exempt → 403
  3. 인증Authentication폼 로그인 세션 또는 HTTP Basic. 5회 실패 시 15분 잠금Form sign-in session or HTTP Basic. 5 failures lock the account for 15 minutes → 401
  4. 계정 상태Account status지워지거나 중지된 계정은 바로 로그아웃Removed or suspended accounts are signed out immediately → 401
  5. 메뉴 권한Menu permission경로 → 메뉴 → 없음 · 조회 · 실행 판단. 표에 없는 경로는 관리자만Path → menu → None · View · Execute. Paths not in the table are admin-only → 403 FORBIDDEN
  6. 비밀번호 변경Password change관리자가 만든 계정은 먼저 비밀번호를 바꿔야 함Accounts created by an admin must change the password first → 403 PASSWORD_CHANGE_REQUIRED
  7. 실행자 기록Executor record로그인 이름을 실행자로 기록 — 헤더로 바꿀 수 없음The signed-in name is recorded as executor — cannot be overridden by a header

공개 경로: /login · /logout · /setup · /ui-assets/** · /actuator/health/** 와 로그인 안내서.Public paths: /login · /logout · /setup · /ui-assets/** · /actuator/health/** and the sign-in guide.

7업체 이관 프로젝트 구성Vendor project structure

업무구분 하나가 패키지 하나(플러그인)가 되고, 테이블마다 Source SQL · Target SQL · (선택) Processor 를 둡니다. Reader · Writer 는 엔진이 만듭니다.Each business area becomes one package (plugin); every table gets Source SQL, Target SQL and an optional Processor. Readers and writers are generated by the engine.

# 예시 레이아웃example layout
acme-migration/
├── libs/                         # Georu bundle (Maven layout)
├── build.gradle
└── src/main/
    ├── java/com/acme/migration/
    │   ├── MigrationApplication.java
    │   ├── common/               # transformation utils · audit columns
    │   └── member/               # one business area = one plugin
    │       ├── MemberPlugin.java # plugin + TableOptions
    │       ├── dto/
    │       └── processor/
    └── resources/
        ├── application.yml
        ├── application-prd.yml
        ├── mapper/member/source/  # Source SQL
        ├── mapper/member/target/  # Target SQL
        └── scenarios/*.json       # run order
