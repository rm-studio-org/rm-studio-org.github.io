Georu/아키텍처Architecture

핵심 기능Core features

Georu 가 사고를 막는 방식 — 동시 실행을 막는 실행 게이트, 읽기와 쓰기를 나누는 이관 엔진, 큰 테이블을 나누는 분할 실행, 실패 뒤 자동 · 수동 복구, 적재 전에 검증하고 DB 를 지키는 안전장치입니다.How Georu prevents accidents — an execution gate against concurrent runs, an engine that separates reads from writes, split runs for large tables, automatic and manual recovery after failures, and safeguards that verify before loading and protect the databases.

8실행 통제Execution control

이관 사고의 상당수는 "두 사람이 동시에 돌렸다"에서 시작합니다. Georu 는 실행 단위를 시스템 전체에서 하나만 허용하고, 실행 전에 정해진 순서로 검사를 돌린 뒤에야 Job 을 시작합니다.Many migration accidents start with "two people ran it at the same time". Georu allows exactly one execution unit system-wide, and only starts a Job after running checks in a fixed order.

9이관 엔진Migration engine

테이블 하나가 Spring Batch Job 하나입니다. 엔진은 읽기와 쓰기 사이에 메모리 큐를 두어 둘을 분리합니다. 소스는 PK 순서로 꾸준히 읽고, 여러 적재 스레드가 큐에서 꺼내 타겟에 배치로 씁니다. 느린 타겟이 소스 커서를 오래 붙잡지 않고, 적재 병렬도는 타겟 여유에 맞춰 조절할 수 있습니다.One table is one Spring Batch Job. The engine puts an in-memory queue between reads and writes. The source is read steadily in PK order, while several load threads take rows off the queue and batch-write them to the target. A slow target never holds the source cursor for long, and write parallelism can be tuned to the target's capacity.

10분할 · 묶음 실행Splitting · group runs

큰 테이블과 여러 테이블을 한 번에 옮기지 않습니다. 기간으로 나누거나 단계로 묶어 Job 여러 개를 차례로 돌리고, 묶음 ID 로 진행과 결과를 한꺼번에 봅니다.Large tables and many tables are not moved in one shot. They are split by period or grouped into steps, running several Jobs in sequence, with progress and results tracked under a group ID.

DIV

날짜 분할Date split

기간을 일 · 주 · 월 · 년 구간으로 나눠 구간마다 Job 하나. 앞 Job 이 끝나면 다음 Job. 묶음 ID DIV-. 구간 실패 시 onUnitFailure 로 멈춤 · 계속을 고름.Splits a period into day · week · month · year ranges, one Job per range, run back-to-back. Group ID DIV-. On a range failure, onUnitFailure picks stop or continue.

SCF

시나리오Scenario

단계 → 단계 안 여러 테이블. 단계 실패 시 기본은 전체 멈춤(선택: 다음 단계). 사전 확인 · 단계별 덮어쓰기. 묶음 ID SCF-.Steps → several tables per step. By default a step failure stops everything (optional: next step). Pre-confirmation · per-step overrides. Group ID SCF-.

⏱

스케줄Schedule

Cron 등록 · 일시정지 · 재개 · 즉시 실행. 재기동하면 일시정지 상태로 올라와 의도치 않은 실행을 막습니다.Cron registration · pause · resume · run now. After a restart schedules come up paused, preventing unintended runs.

XLS

엑셀 이관Excel migration

업로드(헤더 = TOBE 컬럼) → 검증(헤더 · 필수 · 길이 · 타입 · PK 중복) → DB 이관과 같은 파이프라인으로 적재.Upload (header = TOBE columns) → validation (header · required · length · type · duplicate PK) → loaded through the same pipeline as DB migration.

11재시도 · 재실행 · 복구Retries · re-runs · recovery

실패 대응은 자동에서 수동 순으로 쌓여 있습니다. 일시적인 오류는 엔진이 스스로 넘기고, 사람이 개입해야 할 때도 지우지 않고 빠진 행만 채우는 방법이 먼저입니다.Failure handling is layered from automatic to manual. Transient errors are absorbed by the engine, and when people must step in, the first option is to fill only the missing rows — without deleting anything.

11.1 실패 대응 (자동 → 수동)11.1 Failure handling (automatic → manual)

#대응Handling동작Behavior

2오류 유형별 재시도Retry by error type오류를 분류해 유형별로 재시도 (기본 3회 · 1초 · 2배)Classifies errors and retries per type (default 3 × · 1 s · ×2)
3시간대 자동 재시작Run-window restart금지 시간대로 멈춘 실행을 허용 시간대에 다시 시작Restarts a run paused by a blocked window in the allowed window
4빠진 행 채우기Fill missing rows실패한 실행의 요청 그대로 다시 읽고, 타겟 PK 로 이미 있는 행은 걸러 없는 행만 적재. 새 실행으로 남기고 원 실행과 연결Re-reads with the failed run's exact request, filters out rows already in the target by PK, loads only missing ones. Recorded as a new run linked to the original

12.2 실행 전 점검12.2 Precheck

사용 중In use→이관 상태Status→미완 코드Unfinished code→타겟 정의 · 기존 건수 · INSERT 구조Target definition · count · INSERT shape→소스 샘플Source sample→변환Transform→값 점검Value checks→판정Verdict

값 점검은 길이 · NOT NULL · 타입 · PK 중복을 봅니다. 타겟 · 소스를 나눠 돌릴 수 있고(타겟만이면 소스 쿼리 0), 점검 전용 Processor 와 변환 시간 제한(30초)을 씁니다. 쓰지 않는다는 근거로 접속 기록과 실행하지 않은 INSERT 문을 결과에 남깁니다. NORMAL 실행 직전에는 자동으로 돕니다.Value checks cover length · NOT NULL · type · duplicate PK. Target and source can run separately (target-only means zero source queries), with a check-only Processor and a 30 s transformation limit. As evidence that nothing is written, the result keeps the connection record and the INSERT statements that were not executed. It runs automatically just before a NORMAL run.
