04 — Open Source

Georu — DB 이관 프레임워크Georu — a DB migration framework

실제 이관 프로젝트(Oracle → MySQL, MSSQL → MySQL)에서 쓰던 엔진을 고객사 코드와 분리해 공개한 Spring Batch 기반 프레임워크입니다. A Spring Batch–based framework, extracted from the engine we used on real migration projects (Oracle → MySQL, MSSQL → MySQL) and released separately from client code.

거룻배처럼, 데이터를 조금씩 나눠
안전하게 나르는 DB 이관 프레임워크Like a lighter boat — moving data
safely, a little at a time.

시스템을 바꿀 때마다 이관은 SQL 스크립트 묶음과 엑셀 대사표로 다시 만들어지고, 매번 같은 사고가 납니다. 두 사람이 동시에 돌리고, 테스트하다 운영 데이터를 덮고, 몇 건이 빠졌는지 끝나고 나서야 압니다.Every system replacement rebuilds the migration from loose SQL scripts and spreadsheet reconciliations — and the same accidents repeat: two people run it at once, a test overwrites production data, and missing rows surface only at the end.

Georu 에서 사람이 쓰는 것은 변환 규칙(SQL · Java) 뿐입니다. 실행 · 안전장치 · 기록 · 보고는 프레임워크가 맡습니다.With Georu, people write only the transformation rules (SQL · Java). Execution, safeguards, history and reporting are handled by the framework.

거루 (거룻배)Georu — 거룻배, a lighter boat

돛을 달지 않은 작은 배입니다. 큰 배가 닿지 못하는 곳까지 노를 저어 짐을 조금씩 나눠 날랐습니다.A small, sail-less Korean boat that rowed cargo, a little at a time, to places big ships could not reach.

Georu 도 큰 DB 를 한 번에 옮기지 않고 청크(기본 200건) 단위로 나눠, 출발 전에 점검하고 도착할 때마다 기록하며 나릅니다.Georu works the same way: instead of moving a large database at once, it ships chunks (200 rows by default) — checking before departure and recording every arrival.

01안전하게Safe

  • 실행 게이트 — 한 번에 하나만 실행, 다른 실행 중이면 거절(409)
  • 실행 전 점검 — 컬럼 길이 · NOT NULL · 타입 · PK 중복, 타겟 기존 데이터 경고
  • 지우지 않음 — TRUNCATE · DELETE 를 실행하지 않습니다
  • Run gate — one run at a time; concurrent requests are rejected (409)
  • Pre-flight checks — column length, NOT NULL, type, PK duplicates; warns on existing target data
  • Never deletes — no TRUNCATE or DELETE; cleanup stays with people

02코드로As code

  • 테이블당 Source SQL · Target SQL · Processor 세 파일. Reader · Writer 는 엔진이 생성
  • MyBatis SQL 과 Java 라 버전 관리 · 코드 리뷰 · 단위 테스트 그대로
  • 다중 DataSource, N:1 병합, 1:N 복제, 시퀀스 채번
  • Per table: Source SQL, Target SQL, optional Processor. Readers and writers are generated
  • MyBatis SQL and Java — version control, code review and unit tests just work
  • Multiple DataSources, N:1 merge, 1:N fan-out, sequence numbering

03보이게Visible

  • 청크별 진행률, 실행 이력, 로그 · 오류, 빠진 행 채우기
  • 보고서 JSON · CSV · XLSX · PDF, 텔레그램 · UI 알림
  • 운영 UI 와 REST API(Swagger), 메뉴별 권한
  • Per-chunk progress, run history, logs and errors, missing-row backfill
  • Reports in JSON · CSV · XLSX · PDF; Telegram and UI alerts
  • Operations UI and REST API (Swagger) with per-menu permissions

04도구Tooling

  • TOBE 정의 xlsx → 코드 초안 zip 생성
  • 이름 기준 관계 분석, 매핑 정의서 초안
  • 엑셀 · CSV 업로드를 같은 파이프라인으로 적재
  • Generate a code skeleton zip from a TOBE definition xlsx
  • Name-based relationship analysis and mapping spec drafts
  • Load xlsx/csv uploads through the same pipeline
READER_TEST→PROCESSOR_TEST→WRITER_TEST→NORMAL

4단계 테스트 모드 — 읽기만, 변환까지, 최대 100건 적재, 그리고 전량 적재.Four test modes — read only, transform, write up to 100 rows, then the full load.
