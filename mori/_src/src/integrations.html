2[[시작하기||Getting started]]

[[Docker Engine 24 이상과 Compose v2 가 필요합니다. 전체 데모 스택은 4 vCPU · 8GB RAM 을 권장합니다(Wazuh 인덱서를 쓰면 `vm.max_map_count=262144`).||Requires Docker Engine 24+ and Compose v2. The full demo stack recommends 4 vCPU · 8 GB RAM (`vm.max_map_count=262144` if you run the Wazuh indexer).]]

[[데모 (샘플 데이터)||Demo (sample data)]]

$ git clone https://github.com/saranf/mori-soc.git && cd mori-soc
$ ./scripts/mori-start-demo.sh        # .env → start → schema / seed → worker
# → http://localhost:18000/ui   (admin / 1234, demo only)
$ ./scripts/mori-stop-demo.sh [--keep | --purge]

[[브라운필드 — 기존 스택 위에 얹기||Brownfield — on top of your stack]]

  1. [[환경 파일 준비||Prepare the env file]][[`cp .env.example .env` (필수 값만 있는 `.env.minimal` 도 있음)||`cp .env.example .env` (or the shorter `.env.minimal`)]]
  2. [[소스 연결 정보 입력||Fill in sources]][[예: `MORI_ZABBIX_API_URL=https://zabbix.your-corp.com/api_jsonrpc.php`, `MORI_ZABBIX_API_TOKEN=`||e.g. `MORI_ZABBIX_API_URL=https://zabbix.your-corp.com/api_jsonrpc.php`, `MORI_ZABBIX_API_TOKEN=`]]
  3. [[코어 기동||Start the core]][[`docker compose up -d` — postgres · api · worker 3개만 뜹니다. 설정을 바꾸면 `docker compose up -d mori-worker` 로 재적용합니다.||`docker compose up -d` starts only postgres · api · worker. After changing settings, re-apply with `docker compose up -d mori-worker`.]]
  4. [[push 소스 토큰||Token for push sources]][[`MORI_INGEST_TOKEN` 을 `openssl rand -hex 32` 로 만들어 소스 쪽에도 넣습니다.||Generate `MORI_INGEST_TOKEN` with `openssl rand -hex 32` and configure it on the sending side.]]
  5. [[연결 테스트||Test connections]][[`/admin` 온보딩 카드의 [연결 테스트]로 Zabbix · Fleet 연결을 확인합니다.||Use [Test connection] on the `/admin` onboarding card for Zabbix · Fleet.]]

Wazuh

[[인증서는 `generate-indexer-certs` 서비스가 자동으로 만듭니다. 인증서를 파일 단위로 bind-mount 하지 마세요 — 파일이 없으면 Docker 가 같은 이름의 빈 디렉터리를 만들어 서비스가 `is a directory` 오류로 죽습니다. 디렉터리 단위로 마운트하세요.||Certificates are generated by the `generate-indexer-certs` service. Don't bind-mount certificates as individual files — if a file is missing, Docker creates an empty directory with that name and the service dies with `is a directory`. Mount directories instead.]]

3[[운영 전환||Going to production]]

[[운영 모드는 fail-closed 입니다. 인증이 꺼져 있거나, admin 비밀번호가 약하거나, 예시 값(`change_this_…`)이 남아 있으면 부팅을 거부합니다.||Production mode is fail-closed: it refuses to boot if auth is off, the admin password is weak, or placeholder values (`change_this_…`) remain.]]

[[항목||Item]] | [[설정||Setting]] [[인증 · 데모 끄기||Auth on · demo off]] | `MORI_AUTH_ENABLED=true` · `MORI_DEMO_MODE=false` · `MORI_DEMO_SEED=0` [[계정||Accounts]] | [[강한 `MORI_ADMIN_PASSWORD`||A strong `MORI_ADMIN_PASSWORD`]] [[공개 주소 · 쿠키||Public URL · cookies]] | [[`MORI_PUBLIC_URL=https://…` (Secure 쿠키 · CSRF Origin), `MORI_ALLOWED_ORIGINS`||`MORI_PUBLIC_URL=https://…` (Secure cookies · CSRF origin), `MORI_ALLOWED_ORIGINS`]] [[프로필||Profile]] | [[`MORI_PROFILE=production` — HTTPS 가 없으면 부팅 거부, TLS 프록시 뒤면 `MORI_BEHIND_TLS_PROXY`||`MORI_PROFILE=production` — refuses to boot without HTTPS; behind a TLS proxy set `MORI_BEHIND_TLS_PROXY`]] [[세션 · 시크릿||Sessions · secrets]] | [[`MORI_SESSION_BACKEND=postgres`, 시크릿은 `_FILE` 로 파일 주입 가능||`MORI_SESSION_BACKEND=postgres`; secrets can be injected via `_FILE`]] [[증적 서명||Evidence signing]] | [[`MORI_EVIDENCE_SIGNING_KEY` — 증적 번들 HMAC 서명||`MORI_EVIDENCE_SIGNING_KEY` — HMAC-signs evidence bundles]] HTTPS | [[`docker compose --profile https up -d mori-caddy` — 18443 에서 TLS 종단||`docker compose --profile https up -d mori-caddy` — TLS on 18443]]

4[[백업 · 복구 · 업그레이드||Backup · restore · upgrade]]

[[PostgreSQL 덤프 하나가 곧 전체 백업입니다. `.env` 는 백업에 들어가지 않으니 따로 안전하게 보관하세요.||One PostgreSQL dump is the full backup. `.env` is not included — keep it safe separately.]]

# [[백업||backup]] → backups/mori-soc-YYYYMMDD-HHMMSS.dump
$ ./scripts/mori-backup.sh

# [[복구||restore]]
$ docker compose up -d soc-postgres
$ ./scripts/mori-restore.sh backups/mori-soc-<timestamp>.dump
$ docker compose up -d --build mori-api mori-worker
$ curl -s http://localhost:18000/health
  1. [[업그레이드 전 백업||Back up first]][[덤프를 받고 현재 이미지 태그를 기록합니다.||Take a dump and note the current image tag.]]
  2. [[새 판 기동||Start the new version]]`git pull` → `docker compose up -d --build`
  3. [[확인||Verify]][[`/health` 와 `/admin/schema-migrations` 를 확인합니다.||Check `/health` and `/admin/schema-migrations`.]]

[[스키마는 전진만 하며 자동 다운그레이드는 없습니다. 롤백은 이전 태그로 되돌리고 필요하면 덤프로 복구합니다.||Schema migrations are forward-only with no automatic downgrade. To roll back, return to the previous tag and restore the dump if needed.]]
